# fridgeO 프로젝트 기획안

> 작성일: 2026-11-13  
> 문서 상태: 초안  
> 작성 기준: 현재 프로젝트 코드와 화면 구성을 바탕으로 정리

이 문서는 서비스의 개요, 사용자 문제, 주요 기능, 화면 구성과 향후 결정할 사항을 정리한 기획안이다. 현재 기능은 코드에서 확인한 범위를 의미하며, 실제 실행을 통한 동작 검증 결과는 아니다. 목표 사용자, 개발 우선순위, 확장 기능과 성과 지표는 기획 제안으로 구분한다.

## 1. 프로젝트 개요

### 1.1 서비스 소개

fridgeO는 사용자가 보유한 식재료의 수량과 보관 장소, 기한을 관리하고, 보유 재료와 연관된 레시피를 추천하는 서비스다. 냉장고 속 재료를 쉽게 확인하고 요리에 활용하도록 도와 일상적인 식재료 관리와 메뉴 선택의 부담을 줄이는 것을 목표로 한다.

| 항목 | 내용 |
| --- | --- |
| 서비스명 | fridgeO |
| 한 줄 소개 | 내 냉장고 속 재료를 관리하고, 보유 재료로 요리를 선택하도록 돕는 서비스 |
| 기획 목적 | 식재료 방치를 줄이고, 재료 확인과 메뉴 선택에 드는 수고를 줄인다 |
| 핵심 가치 | 재료 현황 파악, 기한 관리, 보유 재료 활용 |
| 서비스 형태 | 모바일 화면을 중심으로 구성된 웹 서비스 |
| 주요 대상 — 제안 | 식재료 관리에 어려움을 겪는 1인 가구와 자취생, 집에서 요리하는 사용자 |

### 1.2 핵심 이용 흐름

**재료 등록 → 상태 확인 → 요리 선택 → 재료 활용**

식재료 목록을 기록하는 것에서 나아가, 사용자가 남아 있는 재료를 실제 요리에 활용하도록 연결하는 것을 중심으로 한다.

## 2. 기획 배경과 해결하려는 문제

아래 사용자 문제는 현재 서비스 방향을 설명하기 위한 가설이다. 사용자 인터뷰나 설문을 통해 실제 빈도와 중요도를 검증할 필요가 있다.

| 사용자 문제 — 검증할 가설 | 서비스의 해결 방향 |
| --- | --- |
| 어떤 재료가 남아 있는지 기억하기 어렵다 | 냉장고 재료 목록과 수량 확인 |
| 재료의 기한을 놓친다 | 임박·경과 상태 표시와 알림 |
| 재료가 있어도 무엇을 만들지 고민한다 | 보유 재료와 연관된 레시피 추천 |
| 요리에 필요한 재료가 있는지 다시 확인해야 한다 | 레시피에서 보유·미보유 재료 구분 |
| 마음에 든 레시피를 다시 찾기 어렵다 | 북마크와 최근 본 레시피 제공 |

### 추가할 조사 자료

- 식재료 관리 방식과 불편에 대한 인터뷰 또는 설문
- 재료를 사용하지 못하고 버리는 상황과 원인
- 메뉴 선택 시 고려하는 조건
- 기존 재료 관리·레시피 서비스 이용 경험

## 3. 목표 사용자와 사용 상황

### 3.1 목표 사용자 — 제안

| 사용자 유형 | 주요 필요 |
| --- | --- |
| 1인 가구·자취생 | 적은 양의 재료를 관리하고 남은 재료를 활용하고 싶다 |
| 집에서 자주 요리하는 사용자 | 보유 재료를 확인하고 메뉴 선택 시간을 줄이고 싶다 |
| 식재료 관리를 시작하는 사용자 | 복잡한 기록 없이 재료와 기한을 쉽게 확인하고 싶다 |

### 3.2 대표 사용자 예시

장을 본 뒤 남은 재료를 자주 잊고, 퇴근 후 메뉴 선택에 어려움을 겪는 자취생을 대표 사용자로 가정한다. 이 사용자는 등록 과정이 간단하고, 먼저 사용할 재료와 관련 레시피를 빠르게 확인할 수 있어야 한다.

### 3.3 주요 사용 상황

- **장을 본 직후:** 구매한 재료를 등록하고 보관 상태를 정리한다.
- **식사 준비 전:** 기한이 임박한 재료와 추천 레시피를 확인한다.
- **장을 보러 가기 전:** 남아 있는 재료와 부족한 재료를 확인한다.

## 4. 서비스 목표

1. 사용자가 보유 재료의 종류, 수량, 보관 장소와 기한을 쉽게 파악하도록 한다.
2. 기한이 임박한 재료를 확인하고 우선 활용하도록 돕는다.
3. 보유 재료와 레시피를 연결해 메뉴 선택의 부담을 줄인다.
4. 북마크와 사용자 참여 기능으로 유용한 레시피를 저장하고 공유하도록 한다.

## 5. 주요 기능

다음은 현재 코드에서 확인되는 기능 범위다.

| 기능 영역 | 주요 내용 |
| --- | --- |
| 홈 | 기한 임박·경과 재료, 소진 재료, 보유 조미료, 추천 레시피 |
| 내 냉장고 | 재료 검색·정렬, 목록·박스 보기, 조미료 필터, 재료 수정·삭제 |
| 재료 등록 | 재료명 자동완성, 수량, 실온·냉장·냉동 구분, 기한 입력 |
| 레시피 탐색 | 카테고리별 조회, 제목·재료 검색 |
| 레시피 상세 | 조리 시간, 난이도, 인분, 준비물, 보유 재료 여부, 조리 단계, 리뷰 |
| 추천 | 보유 재료와 기한을 반영한 레시피 제안 |
| 사용자 참여 | 레시피 작성·수정, 별점·리뷰, 작성자 팔로우 |
| 개인 관리 | 북마크, 최근 본 레시피, 내 레시피, 프로필 |
| 계정·알림 | 회원가입·로그인, 계정 찾기, 알림 확인·설정 |
| 외부 구매 연결 | 부족한 재료의 쿠팡 검색 결과로 이동 |

### 5.1 추천 기능의 현재 범위

- 로그인 사용자는 수량이 남아 있는 보유 재료와 연관된 레시피를 우선 추천받는다.
- 기한이 가까운 재료와 별점·리뷰 등의 정보를 추천 순서에 반영한다.
- 보유 재료와 연관된 추천이 부족하거나 비로그인 상태이면 별점·리뷰 등을 기준으로 목록을 채운다.
- 현재 추천은 필요한 모든 재료와 수량이 충족된다는 의미는 아니다.

## 6. 주요 사용자 흐름

### 6.1 재료 관리

로그인 → 재료 등록 → 냉장고 목록 확인 → 수량·기한 수정 또는 삭제

### 6.2 요리 선택

홈에서 임박 재료 확인 → 추천 레시피 선택 → 준비물 확인 → 조리 단계 확인

### 6.3 레시피 공유

로그인 → 레시피 작성 → 재료·조리 단계 등록 → 다른 사용자의 북마크·리뷰

### 6.4 부족한 재료 확인

레시피 상세 → 미보유 재료 확인 → 외부 쇼핑 검색으로 이동

### 6.5 추가로 결정할 흐름

요리 후 사용한 재료의 수량을 어떻게 갱신할지 정해야 한다. 재료 정보를 쉽게 갱신할 수 있어야 서비스의 냉장고 목록과 실제 보유 상태가 계속 일치할 수 있다. 조리 후 재료 자동 차감은 향후 확장 후보로 다룬다.

## 7. 화면 구성

### 7.1 주요 메뉴

| 메뉴 | 목적 | 주요 연결 화면 |
| --- | --- | --- |
| 홈 | 재료 상태와 추천 요리를 빠르게 확인 | 알림, 검색, 재료 등록, 레시피 상세 |
| 냉장고 | 보유 재료를 확인하고 관리 | 재료 등록, 재료 수정 |
| 레시피 | 요리를 검색하고 조리 정보를 확인 | 레시피 상세, 작성·수정, 리뷰 작성 |
| 마이페이지 | 개인 정보와 저장·작성 활동을 관리 | 북마크, 내 레시피, 최근 본 레시피, 개인정보, 설정 |

### 7.2 화면별 상세 기획에 포함할 요소

- 화면의 목적과 진입 경로
- 표시할 정보와 주요 버튼
- 버튼을 눌렀을 때의 동작과 이동 경로
- 입력 항목, 필수 여부와 입력 제한
- 로그인 여부와 사용자 권한에 따른 이용 범위
- 데이터가 없을 때의 안내와 다음 행동
- 로딩 중 표시와 저장 중 중복 입력 방지
- 조회·저장 실패 시 안내와 재시도 방법

예를 들어 냉장고에 등록된 재료가 없다면 첫 재료 등록으로 안내하고, 검색 결과가 없다면 검색 조건을 변경하도록 안내한다.

## 8. 서비스 정책과 결정 사항

| 항목 | 현재 확인 내용 및 결정할 사항 |
| --- | --- |
| 기한 명칭 | 화면에 혼용된 ‘유통기한’과 ‘소비기한’의 의미와 표기를 정리한다 |
| 날짜 기본값 | 재료별 기본 보관 일수로 날짜를 제안하며, 사전에 없는 재료는 현재 7일을 사용한다. 제안 날짜의 의미와 사용자 확인·수정 방식을 정한다 |
| 기한 알림 | 현재 코드의 5일 이하 기준과 기한 경과 재료 포함 여부, 중복 알림·읽음·삭제 규칙을 문서화한다 |
| 추천 기준 | 보유 재료 연관 추천과 모든 재료를 갖춘 레시피의 구분, 수량·기한 경과 재료 처리 기준을 정한다 |
| 재료 식별 | 같은 재료의 다른 이름과 단위 차이, 서로 다른 기한으로 중복 등록된 재료의 처리 방식을 정한다 |
| 보유 여부 판단 | 이름으로 보유 여부를 비교하는 현재 방식의 한계와 개선 범위를 정한다 |
| 외부 구매 연결 | 현재 동작인 쿠팡 검색 이동에 맞춰 기획 내용과 버튼 문구를 정리한다 |
| 게시물 관리 | 레시피·리뷰의 수정·삭제 권한과 부적절한 콘텐츠 처리 기준을 정한다 |
| 개인정보·계정 | 수집 정보, 이용 목적, 계정 찾기·탈퇴와 데이터 삭제 기준을 정리한다 |

## 9. 개발 범위와 우선순위 — 제안

이미 구현된 기능도 포함되어 있다. 아래 구분은 기획안에서 강조할 핵심 가치와 우선 검증할 범위를 정하기 위한 제안이다.

| 단계 | 범위 | 검증할 내용 |
| --- | --- | --- |
| 핵심 흐름 | 재료 등록·수정·삭제, 기한 확인, 레시피 탐색·추천 | 재료 관리부터 요리 선택까지 자연스럽게 이어지는가 |
| 이용 편의 | 보유 재료 비교, 북마크, 알림, 검색 개선 | 필요한 정보를 쉽게 찾고 다시 이용할 수 있는가 |
| 참여 기능 | 레시피 작성, 리뷰, 팔로우 | 레시피 공유와 평가가 유용한 콘텐츠 축적으로 이어지는가 |
| 향후 확장 후보 | 조리 후 재료 차감, 장보기 목록, 가족 냉장고 공유, 영수증·바코드 등록 | 사용자 조사 결과를 바탕으로 추가할 가치가 있는가 |

## 10. 성과 지표와 검증 방법 — 제안

목표 수치는 초기 사용성 테스트와 데이터 수집 범위를 정한 후 설정한다.

| 지표 | 확인 목적 | 검증 방법 |
| --- | --- | --- |
| 첫 재료 등록 완료율 | 서비스의 시작 과정이 쉬운지 확인 | 등록 시작·완료 이벤트 측정 |
| 재료 등록 소요 시간 | 입력 부담 확인 | 사용성 테스트와 소요 시간 측정 |
| 냉장고 정보 갱신 비율 | 실제 재료 상태를 지속적으로 관리하는지 확인 | 일정 기간 내 수정·삭제 등 갱신 행동 측정 |
| 추천 레시피 조회·북마크 비율 | 추천이 요리 탐색에 도움이 되는지 확인 | 추천 노출 이후 조회·저장 행동 측정 |
| 재방문율 | 반복 이용 여부 확인 | 합의한 기간 기준의 재방문 측정 |
| 사용자 만족도 | 재료 관리와 메뉴 선택의 편의성 확인 | 인터뷰·설문 |

식재료 폐기 감소를 성과로 제시하려면 사용·폐기 기록이나 별도 설문이 필요하다. 단순 조회·삭제 기록만으로 실제 폐기 감소를 판단하지 않는다.

### 완성 기준 — 제안

- 핵심 흐름인 재료 등록, 상태 확인, 레시피 탐색을 수행할 수 있다.
- 사용자별 재료와 개인 정보가 권한에 맞게 관리된다.
- 빈 화면, 로딩과 오류 상황에서 다음 행동을 안내한다.
- 추천과 외부 구매 연결에 대한 설명이 실제 동작과 일치한다.
- 사용성 검증 결과와 남은 개선 사항이 문서에 기록되어 있다.

## 12. 기대 효과

- 보유 식재료의 종류와 상태를 한곳에서 확인할 수 있다.
- 기한이 임박한 재료를 인지하고 먼저 활용하도록 돕는다.
- 보유 재료와 관련된 레시피를 통해 메뉴 선택의 부담을 줄인다.
- 레시피 저장과 공유를 통해 유용한 요리 정보를 다시 활용할 수 있다.

## 13. 후속 확정 사항

- 기획안의 사용 목적: 학교 제출, 포트폴리오 또는 실제 서비스 운영
- 우선 대상으로 삼을 사용자와 검증할 핵심 문제
- 기한 명칭, 제안 날짜와 알림 처리 정책
- 추천 결과의 의미와 재료 보유 여부 판단 기준
- 요리 후 재료 수량 갱신 방식
- 초기 공개 범위, 담당자와 일정
- 성과 지표의 측정 기간과 목표 수치
